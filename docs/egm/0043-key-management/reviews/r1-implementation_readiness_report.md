## Readiness (`egm-implementation-readiness`)

**Blockers**

- **R-B1, lines 93, 98, 204: `key show` contradicts `runtime::public_key`.** `public_key` (`runtime.rs:127`) returns hex only; line 204 says reuse with "no behaviour change"; line 93 says `key show` also prints the OpenSSH line. The plan does not say what `--print-public-key` prints after the change, what `public_key_is_created_once_and_stable` should assert, the ssh public-line comment field, the output layout, or who creates the data directory (`public_key` goes through `open_store`, which calls `create_dir_all`; `VaraqStore::open` creates it too, so a mistyped `--data-dir` silently creates a store and key).
- **R-B2, lines 98, 200, 203: the "store is locked" refusal cannot be implemented as specified.** `VaraqStore::open` (`varaq_store.rs:45-60`) maps every failure to `StoreError::Backend(String)` built from `{:?}` of `Refusal`; a lock refusal cannot be told apart without string matching. `KeyError` has no "locked" variant, and `keys` receives an already-open store. `varaq_store.rs` and `store/mod.rs` are not in the change table. Line 98 says `show` and `export` are "not guarded" but they open the same store. The interim notice has no exact text or removal condition, and the build order never gates on the verification spike.
- **R-B3, lines 94-95, 202: the CLI shape is under-specified.** The `cli.rs` row omits `export --stdout` (decision 5) and `--public` (still open at line 54); nothing says how clap makes `<file>` and `--stdout` exclusive; `KeyCommand` is undefined (`Mode` derives `Eq`, so fields must be `Eq`); `--data-dir` must be `global = true` for `key import f --data-dir X`; precedence for `--print-public-key` or `--headless` with a subcommand is undefined; whether `Mode::PrintPublicKey` stays is unstated; no cli test cases for the new subcommands.
- **R-B4, line 205: the runtime test cannot work as written.** `run_headless` (`runtime.rs:191`) loops until Ctrl-C on real iroh and returns no peer ID; `build_network` returns early under `WOWFT_NET=memory` before `Identity::load_or_create` (`runtime.rs:93-95` against `108`), so the memory net cannot show which identity loaded. The test must call `Identity::load_or_create` or `runtime::public_key` after the import (not "headless"), and the plan gives no data-dir or `unsafe set_var` (edition 2024) setup. The second test duplicates `public_key_is_created_once_and_stable`.
- **R-B5, lines 217-235: behaviour when the stored secret is missing or corrupt is undefined.** `IdentityError::BadStoredKey` exists for a value that is not 32 bytes; `import` with no existing key prints "old and new peer ids" with no old id; `reset` and `import --force` on a corrupt key cannot compute the old ID (likely the very reason to run them); export "create if missing" (line 219) makes the read-only export a writer; whether `WouldReplace` is error text only or also an exit status is unsaid.

**Major**

- **R-M1, lines 200, 215-235:** `keys.rs` is "pure" but the pseudocode prints, prompts and takes `yes`. Pick one: return data and let `lib.rs` print, or take a writer. The confirmation prompt has no home (how stdin is read, prompt text, accepted answers, non-terminal stdin); tests must cover "reset without `--yes` aborts"; no stdout function is listed.
- **R-M2, lines 199, 241:** dependencies unpinned and possibly conflicting. `ssh-key` is "to be confirmed", given only `ed25519`; writing and parsing probably need `alloc` or `std`, and rejecting an encrypted file needs `encryption`. `ed25519-dalek = "3.0.0"` and `rand = "0.10.4"` are in use while `ssh-key` and `age` may pull `ed25519-dalek` 2.x and `rand_core` 0.6 (duplicate versions). Convert via raw seed bytes (`Ed25519Keypair::from_seed`); `Cargo.lock` is not listed; the OpenSSH `comment` is unspecified; Part 2 adds `age` with `ssh` and `armor` with no version while line 52 still questions beta status.
- **R-M3, lines 94, 220-221:** file-creation security is not pinned. Owner-only and refuse-to-overwrite must be one atomic `create_new(true)` open with `mode(0o600)` (`VaraqStore` already uses `OpenOptions` with `mode(0o600)`); a `chmod` after writing leaves a window and `exists()` then `write` is racy. Not covered: a partial file on write failure, relative-path and missing-parent behaviour, Windows.
- **R-M4, line 256:** the `keys.rs` tests are not enumerated ("every refusal case"). Missing: mode 0600 (`#[cfg(unix)]`), existing-file refusal, wrong-key-type fixture (RSA or ECDSA), malformed or truncated file, encrypted fixture, how fixtures are produced, trailing data after the PEM block, CRLF endings, `import` with no existing key, `--force`, unchanged store after a failed import, `--stdout` output and stderr separation, and a fixed known vector (a round trip alone passes if both directions are wrong).
- **R-M5, line 201:** the `identity.rs` functions are unnamed (no signatures); "atomic replace semantics" is claimed but `Store::put` durability and atomicity on `varaq` are not verified; which callers change with `S: Store + ?Sized` (`runtime.rs:109,129,142,193`) is unstated; whether `reset` reuses `Identity::generate` is unstated.
- **R-M6, lines 242-244, 106:** Part 2 gives no API or key-conversion step. The `age` ssh recipient is normally parsed from an OpenSSH public-key string and has no constructor from 32 raw bytes, so the implementer must build `ssh-ed25519 <base64>` and parse it. Not given: function name and signature, input and output types, error enum, who picks the filename and date format, `.age` against armored text. `app/src/scans/*` and the `server/` route do not exist yet (owned by tickets 0039 and 0040), so they cannot be a write allowlist; "`export_tests.rs` or inline" leaves a placement choice; an invalid `BUILTIN[0]` (not a curve point) is not covered.
- **R-M7, lines 207-213:** documentation and ticket rows lack the precise edits (exact text and placement for the ADR 0039 row and the README backup process); "New small tickets" and the `dyn Store` ticket have no filenames or numbers.
- **R-M8, lines 254-259:** phasing does not leave every phase buildable. Step 1 needs `mod keys;`, the `Cargo.toml` dependency and the `identity.rs` replace function, none placed in it; `reset` is built in `keys.rs` but scheduled in step 2; the `varaq` two-openers spike is not in the build order though line 51 says it is "checked first".

**Nit:** R-N1 (line 193) the ADR 0038 and ticket edits are listed only under Part 2 and not assigned to a build step; R-N2 (268-283) alternatives sit under Detailed Implementation; R-N3 (263) `cargo test --lib runtime::` also runs network and server tests, and state whether the whole `cargo test --lib` is expected before merge; R-N4 (208) "update the line" does not quote the line; R-N5 (206) the `trusted.rs` module doc (lines 5-6, 16) also says `--print-public-key`.
